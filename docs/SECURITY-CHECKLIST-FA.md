# چک‌لیست امنیت و انتشار — هم‌قدم

- هیچ secret در سمت کاربر یا فایل APK قرار نگیرد.
- نقش مدیر/پشتیبان فقط از `app_metadata` معتبر یا policy سرور خوانده شود؛ نه از `user_metadata` قابل‌ویرایش کاربر.
- برای هر جدول جدید RLS فعال و تست مالکیت/عضویت اجرا شود.
- قبل از اجرای migration روی دیتابیس اصلی backup داشته باش.
- تست استاتیک مجوزهای SQL را با تست واقعی دو کاربر و نقش مدیر جایگزین نکن.
- Upload کتاب فقط از bucket خصوصی `hg-user-books` و مسیر `{auth.uid()}/...` مجاز است؛ لینک دانلود باید پس از تأیید دسترسی ساخته شود.
- جدول `hg_points_ledger` و `hg_audit_events` به‌صورت مستقیم برای نوشتن از authenticated بسته‌اند؛ امتیاز را از UI نپذیر.
- هر شکست شبکه باید به‌صورت خطا نمایش داده شود، نه موفقیت ساختگی.
- قبل از انتشار عمومی، npm test، npm run build، تست Auth، تست RLS، تست Storage و build APK با گزارش سبز واقعی اجرا شوند.
