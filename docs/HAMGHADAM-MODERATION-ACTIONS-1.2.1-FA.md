# راهنمای نظارت، گزارش و اقدامات مدیریتی چت عمومی هم‌قدم — نسخهٔ ۱.۲.۱

## افزوده‌های این بسته

- گزارش پیام کاربران دیگر همراه با دلیل، توضیح تکمیلی و جلوگیری از ثبت گزارش تکراری برای همان پیام.
- صف گزارش‌های باز/درحال بررسی؛ ناظر می‌تواند گزارش را «در حال بررسی»، «رسیدگی‌شده» یا «ردشده» کند.
- حذف نرم پیام توسط نقش ناظر؛ متن پیام با عبارت حذف‌شدن جایگزین می‌شود و ردیف حذف فیزیکی نمی‌شود.
- ثبت هشدار هفت‌روزه، سکوت یک‌ساعته یا ۲۴ساعته در اتاق مربوط، اخراج موقت ۲۴ساعته از اتاق، و محرومیت بدون انقضا از گفت‌وگوی عمومی هم‌قدم (این اقدام به‌تنهایی ورود کلی حساب Supabase یا ماژول‌های چت خصوصی را مسدود نمی‌کند).
- فهرست سوابق ۴۰ اقدام اخیر شامل فعال، لغوشده و منقضی؛ امکان لغو اقدام فعال و حفظ سابقه. کاربر نیز می‌تواند اعلان اقدام فعال حساب خودش را ببیند و تازه‌سازی کند.
- اجرای سکوت، اخراج و محرومیت در سیاست‌های RLS سمت پایگاه داده و نه صرفاً با مخفی‌کردن دکمه در رابط.
- اعمال محدودیت بر ارسال پیام/پیوست و دسترسی به اتاق/پیوست، طبق اقدام فعال.
- ثبت نقش و هویت ناظر با `app_metadata` سروری؛ `user_metadata` قابل‌تغییر کاربر برای مجوز مدیریتی استفاده نمی‌شود.

## نصب از گوشی

1. ZIP را در ریشهٔ مخزن `nagshe-negar/rahe-talabegi` با نام دقیق `hamghadam-phase1.zip` آپلود و commit کن: `https://github.com/nagshe-negar/rahe-talabegi/upload/main`
2. در GitHub → Actions اجرای `Install Hamghadam Phase 1` را باز کن. سبزشدن test و build لازم است؛ صرفِ آپلود یعنی نصب موفق نیست.
3. اگر workflow شکست خورد، ZIP را دوباره آپلود نکن؛ خطای نخستین مرحلهٔ قرمز را بررسی کن.

## راه‌اندازی Supabase (مرحلهٔ جداگانه و ضروری)

1. از پروژهٔ درست پشتیبان بگیر و مطمئن شو ref همان `gnbwcupxtbsjdgnncort` است.
2. ابتدا `20261029140000_public_chat_moderation_and_reports.sql` و سپس `20261029160000_public_chat_moderation_actions.sql` را بررسی و به‌ترتیب در محیط آزمایشی اجرا کن.
3. پس از backup و تطبیق سیاست‌های موجود، migration گزارش، سپس migration اقدامات ناظر و سپس migration سقف گروه مباحثه و در پایان migration محافظت از نقش‌های هدف را در SQL Editor پروژهٔ صحیح اجرا کن. GitHub Actions برای ایمنی آن‌ها را روی دیتابیس زنده اجرا نمی‌کند.
4. از یک حساب معمولی و یک حساب با نقش امن در `app_metadata` تست کن: گزارش، صف گزارش‌ها، هشدار، سکوت، اخراج، محرومیت، لغو اقدام و پیوست.
5. نقش‌های مورداعتماد پیش‌فرض عبارت‌اند از `admin`, `super_admin`, `chat_moderator`, `content_moderator`, `support`. migration چهارم همچنین خودمحدودسازی و اقدامات ناظر رده پایین‌تر علیه مدیر/ناظر را در سمت پایگاه داده رد می‌کند و RPC پیوستن گروه را با ظرفیت استثناکنندهٔ مسئول بحث هم‌راستا می‌سازد. قبل از اجرا مطمئن شو این نام‌ها با نقش‌های واقعی پروژه سازگارند.

## احتیاط‌های مهم

- بسته، ساختار داده را reset نمی‌کند و جدول یا پیام موجود را حذف نمی‌کند؛ با این حال policyهای مشخص‌شدهٔ چت عمومی را بازتعریف می‌کند، پس قبل از اجرا مقایسهٔ RLS الزامی است.
- «محرومیت از چت عمومی» فقط اتاق‌ها/پیام‌های چت عمومی را در بر می‌گیرد؛ جایگزین مسدودسازی ورود کل حساب به احراز هویت Supabase یا چت‌های دیگر نیست.
- هشدار هفت‌روزه به‌صورت اعلان در حساب هدف نمایش داده می‌شود، اما به‌تنهایی مانع ارسال پیام نمی‌شود. سکوت، اخراج و محرومیت توسط سیاست‌های سرور اعمال می‌شوند.
- اجرای محلی تست‌های ایستا و بررسی نحو، جایگزین آزمایش چندحسابی در Supabase واقعی یا ساخت APK در GitHub Actions نیست.


**پیش‌بررسی ظرفیت گروه:** اگر گروهی از قبل بیش از سه عضو عادی داشته باشد، migration سقف گروه عمداً با پیام خطا متوقف می‌شود و هیچ عضوی را خودکار حذف نمی‌کند. آن عضویت را دستی بررسی کن و پس از backup دوباره اجرا کن.
