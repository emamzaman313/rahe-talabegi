# معماری نسخهٔ اندروید و پشتیبانی — راهِ طلبگی

## مرزبندی محصول

1. `source/rahe-talabegi-desktop.html` نسخهٔ مستقل فعلی است و باید بدون تغییر برای استفادهٔ آفلاین باقی بماند.
2. `index.html` کپی مجزای برنامه برای بستهٔ وب/اندروید است. صفحهٔ پشتیبانی در آن نقطهٔ اتصال جداگانه دارد؛ تغییرهای آنلاین به نسخهٔ آفلاین دسکتاپ نشت نمی‌کنند.
3. `source/rahdan.html` نسخهٔ کامل راه‌دان است که داخل HTML برنامه تعبیه شده است. آزمون خودکار تطابق آن را با نسخهٔ منبع بررسی می‌کند.
4. `src/support-chat.js` فقط صفحهٔ پشتیبانی را مدیریت می‌کند و رفتار فرم‌های دیگر برنامه را جایگزین نمی‌کند.
5. `support-admin.html` پنل وب پاسخ‌گویی است؛ ظاهر آن عمومی است، اما خواندن/پاسخ دادن به گفتگوها توسط نقش پشتیبانی در Supabase و سیاست‌های RLS محدود می‌شود.

## مسیر پیام

```text
کاربر اندروید/وب
  -> Supabase Auth (نشست کاربر)
  -> support_conversations (گفتگوی متعلق به کاربر)
  -> support_messages (پیام غیرقابل‌ویرایش از API کلاینت)
  -> Supabase Realtime
  -> صندوق پشتیبانی با نقش معتبر app_metadata
  -> پاسخ کارشناس -> Realtime -> برنامهٔ کاربر
```

## اصول داده و امنیت

- داده‌های شخصیِ موجود در برنامه‌ریز، هدف‌ها، یادداشت‌ها و راه‌دان صرفاً با این بسته به سرور ارسال نمی‌شوند.
- تنها پیام‌ها و فرادادهٔ ضروری برای پاسخ‌گویی به‌صورت آنلاین ذخیره می‌شوند.
- کلاینت فقط به Project URL و کلید publishable نیاز دارد. کلید `service_role` یا secret نباید در `.env.local` کلاینت قرار بگیرد یا در APK بسته‌بندی شود.
- RLS روی هر دو جدول فعال است. کاربر فقط گفتگوهای مربوط به شناسهٔ خودش را می‌خواند؛ نقش پشتیبانی از `app_metadata.role` خوانده می‌شود، نه `user_metadata`.
- پیام‌ها پس از ثبت، از API عمومی کلاینت قابل تغییر یا حذف نیستند. متن قبل از نمایش در HTML escape می‌شود.
- نقش پشتیبانی باید فقط توسط مالک/مدیر پروژه و از مسیر مدیریتی معتبر تعیین شود. حساب پشتیبانی را عمومی یا مشترک نکن.

## ساخت اندروید

Vite خروجی وب را در `dist/` می‌سازد؛ Capacitor آن را به پروژهٔ Android منتقل می‌کند. پوشهٔ `android/` عمداً در این مخزن خروجی از پیش‌ساخته نشده است؛ آن را روی رایانه‌ای با Node/npm و Android Studio/Android SDK با `npx cap add android` تولید کن. بعد از `npx cap sync android` پروژه را در Android Studio باز کن و APK را از Build menu بساز.

## وضعیت و محدودیت

این معماری و مهاجرت دیتابیس آمادهٔ بررسی‌اند، اما تا زمان ایجاد پروژهٔ واقعی Supabase، قراردادن URL/کلید publishable، اجرای migration و آزمایش با دو حساب جدا، چت هنوز به سرور واقعی متصل نیست. نسخهٔ APK نیز در این محیط ساخته نشده است؛ SDK اندروید در محیط ساخت حاضر نبود و دسترسی به دریافت وابستگی‌های npm نیز موفق نشد.
